PATIENT MONITOR SIMULATOR - how to start it (no internet needed)
1. Double-click "Start Simulator". A black Terminal window opens and the simulator opens in the web browser.
2. If macOS says it cannot open "Start Simulator": right-click it (or Control-click), choose Open, then Open again.
   If it still refuses: Apple menu > System Settings > Privacy & Security > scroll down > "Open Anyway".
3. If macOS asks whether Terminal may access files (on a USB stick, Desktop or Documents), click OK / Allow.
4. Leave the black Terminal window open while you use the simulator.
5. If the browser does not open by itself, open Safari or Chrome and type the address shown in the black window
   (it looks like 127.0.0.1:8642).
6. To stop: close the black Terminal window (click "Terminate" if asked). Closing the browser alone does not stop it.
7. If nothing works, use the rescue card; the recorded cases are in the "videos" folder.

LEARNERS' PHONES (optional; needs Node.js 22 or later on this Mac, and a network the phones share with it)
   Before the day: in Terminal, "node -v" must print v22 or later; if not, install the LTS from nodejs.org. Test it the
   day before with your own phone on the network you will use (the venue Wi-Fi, or this Mac's hotspot).
8. Instead of "Start Simulator", double-click "Start Classroom". If macOS asks whether "node" may accept incoming
   network connections, click Allow. The QR code points at THIS Mac: phones must be on the same network.
9. On the Monitor view, move the pointer to the top edge and click "Phones" (or "Phones" at the top right of the other
   views): a QR code fills the screen. Learners scan it; their phones show the monitor and follow your case.
10. Phones start with their sound off; each learner taps "Sound off" to hear it. Close the QR with "Close".
11. If "Start Classroom" says it cannot start, use "Start Simulator": everything works except the phones.

WINDOWS (a backup for a Windows PC; needs Node.js 22 or later on that PC)
Windows launcher: untested on Windows at this release; test on the room's PC before the day (checklist below).
   Before the day: install Node.js from nodejs.org (the LTS, version 22 or later, the "Windows Installer (.msi)"; its
   defaults are fine). Unzip the kit first: right-click the .zip > Properties > tick "Unblock" > OK (else Windows may
   warn, or block, at every start), then right-click the .zip > Extract All. The launchers cannot run inside a zip.
W1. Double-click "Start Classroom.cmd" (Windows may hide the ".cmd": it is "Start Classroom", type "Windows Command
    Script"). If Windows says "Windows protected your PC": click "More info", then "Run anyway".
W2. A black window opens, then the simulator opens in the default browser (Edge or Chrome).
W3. If Windows Defender Firewall asks about "Node.js JavaScript Runtime": tick BOTH "Private networks" and "Public
    networks", then click "Allow access" (it may ask for an administrator). Without it, phones cannot connect. If the
    question was cancelled once, Windows blocks node.exe silently from then on: fix it as in checklist line 6.
W4. Phones: the black window lists "learners' phones reach it at: http://192.168.x.x:8650/". Phones scan the QR code
    (Monitor view, "Phones") or type that address. They must be on the same Wi-Fi as this PC, or on this PC's own
    Mobile hotspot (Settings > Network & internet > Mobile hotspot; its address is then usually 192.168.137.1).
W5. To stop: close the black window (or press Ctrl+C in it, then Y). Closing the browser alone does not stop it.
W6. Without phones: double-click "Start Simulator.cmd" instead (this PC only; no firewall question).

OWNER'S TEST CHECKLIST FOR WINDOWS (on the room's PC, before the day; report any line that fails, with a photo)
[ ] 1. In a Command Prompt, "node -v" prints v22 or later (if not: install the LTS from nodejs.org, open a new prompt).
[ ] 2. The kit is unzipped into a folder whose path has a space in it (e.g. Desktop\PME kit); nothing runs from the zip.
[ ] 3. "Start Simulator.cmd": the browser shows the simulator at 127.0.0.1:8642, and no firewall question appears.
[ ] 4. Close that black window: within a few seconds a reload of 127.0.0.1:8642 no longer loads.
[ ] 5. "Start Classroom.cmd": the window says "THE CLASSROOM IS RUNNING"; the browser opens 127.0.0.1:8650/?relay.
[ ] 6. Windows Security > Firewall & network protection > "Allow an app through firewall": "Node.js JavaScript
       Runtime" is ticked for BOTH Private and Public (if it is missing or unticked: "Change settings", tick both).
[ ] 7. The "phones reach it at" address is this PC's Wi-Fi IPv4 address ("ipconfig", the Wi-Fi adapter's line).
[ ] 8. Your own phone on that network scans the QR code: it shows the monitor and follows the case within seconds.
[ ] 9. Ctrl+C in the black window, then Y: the window closes, and a reload of 127.0.0.1:8650 no longer loads.
[ ] 10. Start Classroom twice (the first still running): the second window says port 8651 and also runs; close both.
