Finding KR-A1 (kit round A; reproduced 2026-10-12 on kit b8c9c04a and 2026-10-13 on kit 56f3761f, node v26.8.2, macOS): the kit's server/relay.mjs stops at the first client WebSocket frame of 32 bytes or more.

Reproduce: node <kit>/server/relay.mjs --port 8770 --static <kit>/app ; open http://127.0.0.1:8770/?relay#/teach in Chromium; the relay exits; a phone page /?join=<code> then gets ERR_CONNECTION_REFUSED. 'Start Classroom.command' runs the same file, so the classroom stops when the instructor's page opens.
Cause: relay.mjs line 140: const require$$1 = getAugmentedNamespace(__viteOptionalPeerDep_bufferutil_ws$1). Vite bundled ws's optional peer dependency 'bufferutil' as an empty stub, so ws's try { require('bufferutil') } succeeds and unmask() calls an undefined function for any client frame >= 32 bytes. The same line is in the 51a37063 (Stage 12 owner kit), cb4fb17e (Stage 13), b8c9c04a and 56f3761f kits.
Why no gate caught it: Stage 12's phone-room test runs the SOURCE relay (packages/controller/relay/bin.ts with node_modules ws, no bufferutil installed, so ws falls back to its JS unmask); the kit check (Stage 12 T8) fetched /pme-relay.json and /?join= over HTTP only, no WebSocket frame.
Workaround used for the kit-round measurements: WS_NO_BUFFER_UTIL=1 in Start Classroom's environment (ws then uses its JS unmask: the phones join and follow). The kit as built does not set it. Fix belongs to the kit builder (scripts/showcase/make-bundle.mjs relay build) or the launcher: not done here (no product code in this round).
